# 目录与装载次序

## 〇、你拿到的目录长这样

```
<发行包>/
├─ LuaWAG-Luminosa-ver0.1.0/     ← 运行框架（引擎 + 脚本库，**带版本号**）
│  ├─ LuaWAG.exe
│  ├─ SDL3.dll / lua51.dll
│  ├─ Luminosa/                  ← 脚本层（下面四层就在里面）
│  └─ debug/                     ← 诊断导出（开了 --diagnostics 才有）
└─ Tools/                        ← 给你用的工具（与框架**并行**）
```

**三条约定：**

| # | 约定 |
|:--:|---|
| ① | **版本写在目录名上**，不写在任何文件里。`ver0.1.0` 是**框架版本**，与引擎版本无关 |
| ② | **升级时**：同版本补丁只覆盖 `exe` / `dll`；跨版本时连 `Luminosa/{WagLib,Lumi,Nosa}` 一起换 —— 但 **`Luminosa/Project` 永远保留**（那是你的游戏） |
| ③ | **`Tools` 与框架并行**，不属于脚本层。工具独立发布也扔这里 |

> 推荐升级姿势：**解压新框架目录 → 把旧目录的 `Luminosa/Project` 拷进去 → 删旧目录**。
> 比“原地覆盖”安全：不会出现“新 exe + 旧脚本”，选错了也还能回退。

## 一、四个目录

```
<安装根>/Luminosa/
├─ WagLib/     引导层（引擎自带：harden / hooks / boot / vocab / load / resolve …）
├─ Lumi/       官方增强库（Basic/ 下有 object / rng / shader / font / atlas / text …）
├─ Nosa/       第三方增强库
└─ Project/    你的游戏
```

`<安装根>` = **exe 所在目录** = 那个 `LuaWAG-Luminosa-ver…/`。

| 目录 | 谁写的 | 你能改吗 |
|---|---|---|
| `WagLib` | 引擎 | **不改**（它负责找到并装载下面三层） |
| `Lumi` | 官方 | 可以用；建议不改（要改就拷到 `Project` 再改） |
| `Nosa` | 第三方 | 可以用；装进来即可 |
| `Project` | **你** | 随便 |

**引擎按路径直接读取的只有 `WagLib/init.lua`**。  
`WagLib` 自己的模块由它显式 require；`Lumi` / `Nosa` / `Project` 则由扫描器自动装载。

## 二、装载次序

| 步骤 | 发生什么 |
|:--:|---|
| 0 | 引擎预置 13 个钩子槽为**空函数** |
| 1 | `harden`：环境封堵（必须在任何用户脚本之前） |
| 2 | `hooks`：自检“槽是不是函数” |
| 3 | `boot`：引导期配置（视口；此时只能用引擎原语） |
| 4 | `vocab`：装配用户词汇（`MainFrameFunc` 之类） |
| 4.5 | 装配 `lumi.screen` |
| 4.6 | 装配 `wag.text` |
| 5 | 按层装载 `Lumi` → `Nosa` → `Project`（递归扫描 `.lua`） |
| 5.6 | 安装默认策略（拖拽即暂停；有安全阀） |
| 5.7 | 调用 `on_game_init`（此时层已装载完成） |
| 6 | `WagLib/init.lua` 显式请求进入帧循环（`wag.boot.run()`） |

> **步骤 6 是显式的**：`WagLib/init.lua` 在装载成功后才会调用 `wag.boot.run()`。  
> 这也意味着“装载中途失败”与“可以开始跑”是两个不同状态。

## 三、目录扫描规则

从 2026-11-19 起，`Lumi` / `Nosa` / `Project` **不再需要手工写清单或显式 require**。  
`WagLib/load.lua` 通过 `WagLib/resolve.lua` 调用 `wag.fs.list_files` 递归扫描每个层的目录。

实际行为：

1. 只装载扩展名为 **`.lua`** 的文件；
2. 相对路径统一使用 `/`；
3. 模块名带层前缀：`Lumi/Basic/rng.lua` → `Lumi.Basic.rng`；
4. 模块名按字典序排序后依次 `require`；
5. 单个模块失败记 **L2**，继续装载下一个；
6. 某一层不存在或为空记 **L1**，引擎仍能启动；
7. `WagLib` 自己不被扫描，由 `init.lua` 显式 require。

因此：

```text
Luminosa/Project/main.lua        → 自动装载 Project.main
Luminosa/Project/game/foo.lua    → 自动装载 Project.game.foo
Luminosa/Lumi/Basic/rng.lua      → 自动装载 Lumi.Basic.rng
```

`Project/main.lua` 不需要再自己 `require`，也不需要在文件末尾调用 `wag.boot.run()`；  
帧循环由 `WagLib/init.lua` 的步骤 6 统一请求。

> **不要依赖装载顺序来初始化依赖。**  
> 扫描顺序只是“按模块名字典序”，不是依赖拓扑序。  
> 模块之间需要确定顺序时，在自己的模块里显式 `require` 对方。

## 四、怎么挂钩子

钩子槽是**13 个固定名字**，挂在 `wag.hook` 上。两种写法等价：

```lua
-- 写法一：裸全局名（经用户词汇转发到 wag.hook）
MainFrameFunc = function(info) ... end

-- 写法二：直接赋到槽上
wag.hook.on_frame_main = function(info) ... end
```

> 裸全局名来自 `vocab` 的用户词汇表（如 `MainFrameFunc` / `PauseFrameFunc` / `MainRenderFunc`）。
> 两者写的是**同一个槽**，选一种即可，别混着用。

**槽必须是函数**：赋了非函数 ⇒ 引擎内部完整性错误（L3）。

## 五、最小工程长什么样

```
<安装根>/Luminosa/
└─ Project/
   └─ main.lua        ← 定义钩子即可；会被自动扫描
```

```lua
-- Project/main.lua
local M = {}

function M.main_frame(info)
    -- 每逻辑帧跑一次；info.dtg 恒为 1/60
end

MainFrameFunc = M.main_frame

-- 不要在这里调用 wag.boot.run()：
-- WagLib/init.lua 的步骤 6 会在所有层装载完成后请求进入帧循环。
```

## 六、空层与缺层

缺少某一层是合法状态：

```text
没有 Nosa/        → 只用 Lumi 和 Project，正常
没有 Project/     → 启动空引擎，显示哨兵蓝色
Project/ 空目录   → 同上，Project 层没有可装载模块
```

对应日志是 L1：

```text
[L1] 层目录不存在或为空，跳过：Nosa
```

这不是错误，也不会阻止引擎启动。
