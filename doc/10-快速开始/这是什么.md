# 这是什么（提供 / 不提供 / 谁补）

> **引擎给的是地基，不是成品房。**
> 结构是通用的：帧线、钩子、状态、池、坐标、原语 —— 你盖什么都行。
> **它不塞一套自己的范式让你先学、再绕开。**

---

## 提供（地基）

| 你拿到的 | 说明 |
|---|---|
| **帧线与时序** | 固定 1/60 时间颗粒、三条帧线（Main / Pause / Ext）、渲染与逻辑的固定次序 |
| **13 个钩子** | 每帧该做什么，有固定入口；引擎只在这里回调脚本 |
| **暂停状态机** | 多个"暂停源"按住同一个状态，脚本可以请求 |
| **容器与池** | 固定容量、句柄、生成/回收 |
| **绘制原语** | 画图 / 填色 / 一次提交；层与 z 排序 |
| **坐标与视口** | 逻辑坐标 → 帧缓冲的唯一换算路径 |
| **输入采样** | 每帧一份快照（键盘 / 鼠标 / 手柄） |
| **错误分级与诊断导出** | L1–L4；`--diagnostics` 写 jsonl |
| **原语 + 分层装载** | `wag.*` 原语；`Lumi` / `Nosa` / `Project` 三层 |

## 不提供（在库层，不在引擎）

| 引擎不提供 | 谁补 |
|---|---|
| 编辑器 / 场景编辑器 | 没有，也不打算有 |
| 组件系统 / ECS | `Nosa` 或你自己的 `Project` |
| 精灵动画 / 粒子 | `Nosa` 或 `Project` |
| UI 控件（按钮、列表） | `Project`（`Lumi` 目前只有策略与基础设施） |
| 键位映射层 | `Project` |
| 资源管线 / 打包工具 | 不归引擎管 |
| 任何"游戏类型"的预设 | **不会有** —— 那是世界法则层 |

> **"不提供"不是缺席，是分层的另一端。**
> 库层的东西**不在引擎里**：不 require 就不存在，所以**不用拆水电**。

## 谁补：三个地方

| 目录 | 谁的东西 | 你能做什么 |
|---|---|---|
| `WagLib` | **引导层**（引擎自带） | 读，别改 |
| `Lumi` | **官方增强库** | 用；**可以读源码当范例** |
| `Nosa` | **第三方增强库** | 装进来用 |
| `Project` | **你的游戏** | 随便写 |

---

## 代价（要如实说）

> 与 Unity / UE / Godot 相比，**你要自己决定的东西多得多**。
> 换来一件事：**你的游戏结构不需要迁就引擎**。

- 挡住你的东西，先自己写一个小版本（通常几十到几百行）；
- 将来 `Lumi` / `Nosa` 有了，再换掉 —— **换库不动你的游戏结构**。

---

## 适用边界

它适合任何**能拆成这两件事**的游戏：

1. 每帧推进一点状态（`dtg` 固定 1/60）；
2. 每帧画点什么（或什么都不画）。

反过来，它不适合"靠引擎自带的高级系统拼装"的项目 —— 那些系统这里没有。

---

## 为什么长这样

设计是从**文字冒险**那类"逻辑/状态/文本优先"的需求长出来的，
所以原语是"能表达任何东西"的地基，而不是"图形优先"的工具箱。

⇒ 它只给你"画一张图 / 填一块色 / 交一次批"，不给你"精灵动画""粒子"。
那些属于**你的游戏**，不属于地基。
