# 时序与帧线

> 这一篇讲清楚三件事：
>
> 1. 引擎里到底有哪几个“时间量”；
> 2. 三条帧线是什么；
> 3. 六个大循环分别在什么时候跑、能做什么。
>
> 具体某一种玩法（暂停菜单、拖拽暂停、慢放）在其它文档展开。

---

## 一、时间三分：时间颗粒 / 逻辑帧率 / 渲染帧率

这是三个不同的量，不能混。

| 术语 | 含义 | 可变吗 |
|---|---|---|
| **时间颗粒** | 游戏时间的网格，固定 `1/60` 秒 | **不可变** |
| **逻辑帧率** | 每秒在颗粒上采多少次 | 可变 |
| **渲染帧率** | 每秒实际往屏幕画多少次 | 可变 |

### 1. 时间颗粒

```text
dtg = 1/60
```

它不随窗口大小、目标帧率、机器性能变化。  
你的逻辑每被调用一次，就按 `1/60` 秒推进。

不要把 `dtg` 当成“上一帧到这一帧过了多久”的真实时间。  
真实时间会抖；`dtg` 不会。

### 2. 逻辑帧率

逻辑帧率是“每秒采几个颗粒”。

```text
每秒游戏时间 = 逻辑帧率 × 时间颗粒
```

所以：

```text
逻辑 60 Hz  → 一秒游戏时间推进 1 秒
逻辑 30 Hz  → 一秒游戏时间推进 0.5 秒
逻辑 240 Hz → 一秒游戏时间推进 4 秒
```

引擎不规定“多少 Hz 才叫正常速度”。  
60 Hz 是常见约定，不是引擎硬编码的世界法则。

### 3. 渲染帧率

渲染帧率是“每秒画几次”。

它不改变游戏时间，只改变画面更新频率。  
目标帧率是**请求**，不是保证：

```lua
wag.time.set_target_fps(60)
```

机器跟不上时，实际逻辑帧率和渲染帧率都会低于目标；  
时间颗粒仍然是 `1/60`。

## 二、`dtg` 与 `frame`

### `info.dtg`

```text
恒为 1/60
```

不是真实秒数。  
不要用 `os.clock()` / `os.time()` 替代它做逻辑步进。

### `info.frame`

`frame` 是**正常帧的循环帧号**：

- 每个正常帧 +1；
- 暂停帧不递增；
- 慢放时，被跳过的轮次会看到**同一个 `frame`**。

⇒ `frame` 相同，表示这几轮属于同一个逻辑帧。

## 三、三条帧线

| 帧线 | 什么时候跑 | 用途 |
|---|---|---|
| **Main** | 正常帧 | 世界逻辑 + 场景渲染 |
| **Pause** | 暂停帧 | 暂停菜单逻辑 + 暂停画面 |
| **Ext** | **每帧都跑** | 叠加层：HUD、调试、跨暂停的表现 |

关系：

```text
Main 和 Pause 互斥；
Ext 永远在旁边。
```

注意：

> **Ext 不是“第三个世界”。**  
> 把世界逻辑放进 Ext，暂停时世界仍然会动。  
> Ext 只应该放“暂停时也要继续”的东西。

## 四、六个大循环

这六个名字是游戏代码最常写的入口。

| 大循环 | 对应钩子 | 什么时候跑 | 主要职责 |
|---|---|---|---|
| `ExtFrameFunc` | `on_frame_ext` | **每帧**，逻辑相位最前 | 叠加层逻辑 |
| `MainFrameFunc` | `on_frame_main` | 仅正常帧 | 主世界逻辑 |
| `PauseFrameFunc` | `on_frame_pause` | 仅暂停帧 | 暂停逻辑 |
| `MainRenderFunc` | `on_render_main` | 仅正常帧 | 场景绘制 |
| `PauseRenderFunc` | `on_render_pause` | 仅暂停帧 | 暂停画面 |
| `ExtRenderFunc` | `on_render_ext` | **每帧**，画在所有内容之上 | HUD / 调试 |

对应关系：

```text
ExtFrameFunc   → on_frame_ext
MainFrameFunc  → on_frame_main
PauseFrameFunc → on_frame_pause
MainRenderFunc → on_render_main
PauseRenderFunc→ on_render_pause
ExtRenderFunc  → on_render_ext
```

### 正常帧跑哪些

```text
ExtFrameFunc
MainFrameFunc
MainRenderFunc
ExtRenderFunc
```

### 暂停帧跑哪些

```text
ExtFrameFunc
PauseFrameFunc
PauseRenderFunc
ExtRenderFunc
```

### 每帧都跑哪些

```text
ExtFrameFunc
ExtRenderFunc
```

## 五、一帧的顺序

```text
（事件 / 焦点）
      ↓
ExtFrameFunc          ← 每帧
      ↓
MainFrameFunc         ← 正常帧
  或 PauseFrameFunc   ← 暂停帧
      ↓
OnRenderBegin         ← 每帧，渲染设置
      ↓
MainRenderFunc        ← 正常帧
  或 PauseRenderFunc  ← 暂停帧
      ↓
ExtRenderFunc         ← 每帧
      ↓
OnRenderEnd           ← 每帧，渲染收尾
      ↓
Present
```

`OnRenderBegin` / `OnRenderEnd` 不是六个大循环之一。  
它们是渲染相位的两端：绑定渲染目标、设置状态、解绑、后处理、截图。

### 生命周期

```text
GameInit   在帧循环开始前一次
GameExit   在关闭序列里一次；不保证一定被调用
```

它们收到的是**空表**，没有 `dtg` / `frame` / `event`。

## 六、暂停帧的特殊性

### 1. 暂停不是“世界自己停”

暂停是一条**帧线**：

```text
Main 不跑
Pause 跑
Ext 照跑
```

所以：

- 世界逻辑不会自动推进；
- 暂停菜单可以在 `PauseFrameFunc` 里收输入；
- HUD/动画可以继续放在 Ext 线。

### 2. 引擎不会替你画暂停世界

引擎在暂停帧不会重画你的世界，也不会把上一帧自动贴回来。  
`PauseRenderFunc` 必须自己画：

- 想冻结画面：先把当前世界重新提交一次；
- 想纯色/菜单：画自己的背景。

**什么都不画 ⇒ 黑屏。**

### 3. 暂停状态在帧末生效

`wag.engine.pause()` / `wag.engine.resume()` 都是请求：

```text
本帧读到的状态 = 本帧实际运行的状态
状态切换在帧末生效
```

`resume()` 只松 `user` 位；  
如果还有失焦等源按着，游戏依然是暂停的。

具体暂停源与恢复规则见 `30-时序与时间/暂停与恢复.md`。

## 七、慢放、步进与回放

### 慢放

引擎不提供“慢放开关”。  
慢放是脚本侧门控：

```text
每轮收到 dtg = 1/60
但你不一定每轮都推进世界
```

被跳过的轮次：

```text
frame 相同
世界不动
```

### 回放

rep 记录的是**每个逻辑帧的输入**，不记录渲染帧率，也不记录暂停。  
播放速度是播放期参数，不改变录像里的游戏时间。

---

## 八、必须记住的规则

1. **逻辑用 `dtg`，不用真实时间。**
2. **逻辑状态只在帧钩子里改，不在渲染钩子里改。**
3. **绘制只在渲染钩子里做，不在帧钩子里做。**
4. **Main 和 Pause 互斥，Ext 永远跑。**
5. **Ext 只放叠加层，不要放世界逻辑。**
6. **暂停帧必须自己画暂停画面。**
7. **状态变更在帧末生效，不要在帧中途假设它已经变了。**

## 九、最小骨架

```lua
function GameInit()
    -- 资源、字体、输入绑定
end

function ExtFrameFunc(info)
    -- HUD 动画、调试数据：暂停时也可以继续
end

function MainFrameFunc(info)
    -- 世界逻辑
end

function PauseFrameFunc(info)
    -- 暂停菜单逻辑
end

function MainRenderFunc(info)
    -- 世界绘制
end

function PauseRenderFunc(info)
    -- 暂停画面（必须画）
end

function ExtRenderFunc(info)
    -- HUD / 调试绘制
end
```
