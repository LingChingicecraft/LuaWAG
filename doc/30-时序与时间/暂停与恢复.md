# 暂停与恢复

> 时间颗粒、Main/Pause/Ext 三条帧线与六个大循环见
> `30-时序与时间/时序与帧线.md`。

## 一、状态不是布尔，是“被几个源按住”

引擎内部是一个**位掩码**：**只要还有一位亮着，游戏就是暂停的**。

| 源 | 谁按 | 谁松 | 现状 |
|---|---|---|---|
| **`user`** | 你的脚本（`wag.engine.pause()`） | 你的脚本（`wag.engine.resume()`） | ✅ 可用 |
| **`focus`** | 引擎（窗口失去焦点） | 引擎（窗口重新获得焦点） | ✅ 默认开启 |
| **`drag`** | —— | —— | 保留但从不点亮 |

关键规则：

> `wag.engine.resume()` **只松 `user` 这一位**。
> 如果引擎仍被别的源按住（比如失焦），**游戏依然是暂停的**。
> “撤销一个源”不等于“设回运行”。

## 二、状态在帧末生效

- `pause()` / `resume()` 只是**请求**；
- 本帧读到的状态，就是本帧实际运行的状态（不会帧中途翻转）；
- 同一帧里连续调 `pause()` 再 `resume()`，本帧仍然是原来的状态。

## 三、失焦默认暂停 —— 怎么关

```bash
LuaWAG.exe --no-focus-pause
```

- 这是**启动期**开关（给 CI / 无头场景用）；
- **没有脚本接口**：失焦与否该由启动方式决定，不该由游戏逻辑在运行中翻转。

## 四、暂停帧里引擎不画你的世界

> 最容易踩的坑：引擎在暂停帧不会重画你的世界，也不会把上一帧自动贴回来。
> 而且每帧会先清成信箱黑。

所以 `PauseRenderFunc` 必须自己画：

```lua
function PauseRenderFunc(info)
    -- 想冻结画面：逻辑已停，重新 emit 一遍容器即可
    -- 想要纯色/菜单背景：直接画自己的东西
end
```

**什么都不画 ⇒ 黑屏。**

## 五、最小暂停菜单

```lua
local input = require("WagLib.input")

input.bind("pause", { keys = { "ESCAPE" } })

local function pause_game()
    wag.engine.pause()          -- 请求；帧末生效
end

local function resume_game()
    wag.engine.resume()         -- 只松 user 位
end

function PauseFrameFunc(info)
    if input.press("pause") then
        resume_game()
    end
end

function PauseRenderFunc(info)
    draw_rect(...)              -- 背景 / 菜单
end

function MainFrameFunc(info)
    if input.press("pause") then
        pause_game()
        return
    end
    step_game()
end
```

键位 API 以 `60-输入/输入.md` 为准。

## 六、与“拖拽即暂停”的关系

引擎不会因为拖窗口而暂停。  
要这个行为，用配方：

→ `30-时序与时间/配方-拖拽即暂停.md`

## 七、暂停时的三条纪律

1. **恢复必须显式**（玩家操作），不要写“松手自动恢复”这类逻辑；
2. **不要**在渲染钩子里改暂停状态；
3. **不要**给某个容器/对象加“忽略暂停”的特权 —— 暂停是一条**帧线**，不是逐对象的开关。
