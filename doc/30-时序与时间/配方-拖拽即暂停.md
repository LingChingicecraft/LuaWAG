# 配方：拖拽窗口时自动暂停

## 你要解决的问题

> 玩家拖我的窗口，游戏还在跑 —— 要不要暂停？

**建议要**。理由不是审美：

- 拖拽期间 Windows 在模态循环里，**键盘消息被过滤、鼠标被捕获** ⇒ 玩家**本来就没有输入通道**；
- 让游戏继续跑，只是在跑给没人看；
- 暂停之后，"拖拽期间最坏 1–2 帧的输入延迟"也就彻底没有意义了。

---

## 机制：引擎只给事实

引擎**不会**替你做这件事（`pause_source::drag` 保留但不点亮）。
它只给一个事实：**本帧开始时，用户是否正在拖拽/缩放窗口**。

```lua
info.dragging   -- boolean；拖动标题栏【和】拖拽边框都算
```

> 为什么引擎不自己暂停：如果引擎持这个位，松手时释放就是"自动恢复"（违反"恢复必须显式"）；
> 不释放则脚本松不掉（违反"位只能由持有者释放"）⇒ 只能由**脚本用自己的 `user` 位**实现。

---

## 必须做的两样（一件都不能少）

| # | 做什么 | 不做会怎样 |
|:--:|---|---|
| **D1** | 一条**暂停线**（`on_frame_pause`），并且**在层装载期**设好 | `Lumi/drag_pause` 的安全阀会判"本工程没有暂停线" ⇒ **静默不装** |
| **D2** | 一个**恢复入口**（Esc / 菜单项） | 拖一下窗口 ⇒ 游戏**再也回不来** |

> **D1 + D2 是一对**：只做 D1 = 锁死；只做 D2 = 策略不装。

---

## 推荐再补两样

| # | 做什么 | 为什么 |
|:--:|---|---|
| **D3** | 暂停界面（`PauseRenderFunc`） | 引擎不画暂停背景；不画就是**黑屏** |
| **D6** | 暂停文案"松开后按 Esc 继续" | 拖拽期间键鼠到不了窗口，**只能松手后再操作** |

## 可选

| # | 做什么 | 为什么 |
|:--:|---|---|
| **D4** | 拖拽阈值（如"拖动超过 100 ms 才暂停"） | 防误触（手滑碰一下标题栏） |
| **D5** | 关掉策略 | 不想要这个行为 |

---

## 做法

`Lumi/Basic/drag_pause.lua` 已经给了默认策略（包装 `on_frame_main`），你只要满足 D1/D2：

```lua
-- Project/main.lua
local input = require("WagLib.input")
input.bind("pause", { keys = { "ESCAPE" } })

-- D1：暂停线（层装载期设好，不能等到帧循环开始后）
PauseFrameFunc = function(info)
    -- 暂停时的逻辑：按键恢复
    if input.press("pause") then
        wag.engine.resume()
    end
end

-- D3：暂停画面（引擎不画，必须自己画）
PauseRenderFunc = function(info)
    draw_menu_background()
    draw_text("已暂停　按 Esc 继续")       -- D6 的文案
end

-- 你的正常帧逻辑
MainFrameFunc = function(info)
    step_game()
end

wag.boot.run()
```

**这就是全部**。`info.dragging` 的判断、暂停请求，都由 `Lumi/drag_pause` 做。

### 关掉它

```lua
-- 在 GameInit 里（或任何早于帧循环开始的地方）
require("Lumi.Basic.drag_pause").enabled = false
```

### 加阈值（D4）

`Lumi/drag_pause` 不带阈值。想防误触，自己包一层：

```lua
local drag_ms = 0
local inner = wag.hook.on_frame_main
wag.hook.on_frame_main = function(info)
    if info.dragging then
        drag_ms = drag_ms + info.dtg * 1000
        if drag_ms > 100 and not paused then wag.engine.pause() end
    else
        drag_ms = 0
    end
    return inner(info)
end
```

---

## 验证

1. 启动后日志应出现 **`[Lumi] 拖拽即暂停策略已安装`**；
2. 拖住标题栏 ⇒ 日志出现 **`[Lumi] 拖拽窗口 ⇒ 暂停`**；
3. 松手 ⇒ **游戏不应自己继续跑**（`perf_log.jsonl` 的 `frame` 号停住）；
4. 按 Esc ⇒ 继续跑。

如果第 1 条变成了 **`[Lumi] 未安装拖拽暂停（本工程没有暂停线…）`**，
说明 D1 没做 —— 检查 `PauseFrameFunc` 是不是在层装载期设的。

---

## 陷阱

| 陷阱 | 说明 |
|---|---|
| 暂停线设晚了 | 策略会**静默不装**（你以为装上了）。必须在层装载期设 |
| 只做 D1 不做 D2 | 拖一下就锁死 |
| 指望拖拽中能点菜单 | 键鼠都到不了窗口，只能松手后操作 |
| 暂停时什么都不画 | 黑屏（引擎每帧清成信箱黑，且不画暂停背景） |
