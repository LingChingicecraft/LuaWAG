# 随机数与确定性

## 一、为什么它在"时序"这一章

因为随机数的**失败模式是顺序错误**，不是数值错误：

> 同一个种子，两局跑出不同结果 —— 几乎总是因为**抽签的次序不同**：
> 在渲染钩子里抽了、暂停帧里多抽了一次、慢放时被跳过的那几帧没抽。

⇒ "抽多少、什么时候抽"是**时序问题**，所以这一篇放在这里。

---

## 二、用 `lumi.rng`（官方库）

```lua
local rng = require("Lumi.Basic.rng")

local R = rng.new("main")   -- main / pause / ext

R:Int(1, 6)        -- 1..6（含两端）
R:Float()          -- [0, 1)
R:Bool()           -- true / false
R:Chance(0.1)      -- 10% 概率 true
R:Pick(t)          -- 从数组里取一个
R:Shuffle(t)       -- 原地打乱
R:Sign()           -- +1 / -1
R:Angle()          -- 随机朝向（度）
R:Range(a, b)      -- [a, b) 浮点
```

**状态**：

```lua
local lo, hi = R:State()
R:SetState(lo, hi)
```

引擎提供三条固定流：

| 槽 | 用途 |
|---|---|
| `main` | 主逻辑 |
| `pause` | 暂停逻辑 |
| `ext` | 叠加层 |

不要自己造第四条“战斗流/特效流”去绕开这套划分；  
需要隔离时，在同一流里显式保存/恢复状态，并接受顺序代价。

---

## 三、确定性三条规则

| 规则 | 为什么 |
|---|---|
| **只在逻辑钩子里抽**（`on_frame_main` / `on_frame_pause` / `on_frame_ext`） | 渲染钩子可能因掉帧/尺寸变化被跳过一次或多次，抽签次数就变了 |
| **不要按真实时间抽**（别用 `os.clock()` 决定抽不抽） | 真实时间不是游戏时间 |
| **抽签次数必须是"每逻辑步固定"的** | 你的逻辑要能只根据"这一步做了什么"决定抽几次 |

> 判断方法：把你的逻辑跑两次，输入相同、帧数相同 ⇒ **结果必须逐字节相同**。

---

## 四、`State()` / `SetState()` 什么时候用

- 存档/读档时把随机状态一起存；
- 回放时把起点状态复位；
- 调试时"回到那一帧再跑一次"。

它**不**解决顺序问题 —— 顺序错了，状态存得再准也没用。

---

## 五、想要“每个系统互不干扰”的随机流

引擎侧固定是 **main / pause / ext 三条流**，不是任意条。

如果你的“战斗”和“特效”都在 Main 线，  
又想互不影响，只能在同一个流里做显式保存/恢复：

```lua
local rng = require("Lumi.Basic.rng")
local R = rng.new("main")

local combat_lo, combat_hi = R:State()

-- 切到另一段使用……
local effects_lo, effects_hi = R:State()
R:SetState(combat_lo, combat_hi)

-- 切回来……
R:SetState(effects_lo, effects_hi)
```

这会付出顺序代价：切换时机本身也会影响结果。  
不要把它当成“免费的多流”。

---

## 六、回放需要三样东西

1. **输入**（每帧一份快照）；
2. **帧序**（`dtg` 固定，帧数决定时间推进）；
3. **随机数种子/状态**。

缺任何一样，都无法逐帧复现。输入模块已经落地；输入采样与回放源的约定见 `60-输入/输入.md`。
