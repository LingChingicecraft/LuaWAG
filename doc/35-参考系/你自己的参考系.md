# 你自己的参考系

> 引擎只管"逻辑坐标"这一层（见同目录 `平台给的参考系.md`）。
> **再上面几层随你定义** —— 引擎不解释、不校验、不参与。

---

## 一、引擎不知道的东西

| 你可能想有 | 引擎知道吗 |
|---|---|
| 世界坐标（米 / 格 / 瓦片） | ❌ |
| 摄像机（跟随、缩放、旋转） | ❌ |
| 图层（背景 / 前景 / UI 分别用哪套坐标） | ❌ |
| 3D 透视、倾斜 | ❌ |
| 屏幕分区（左半 / 右半） | ❌ |

这些**都是你的脚本**。引擎只要求最后交出来的 `x / y` 是**逻辑坐标**。

---

## 二、典型做法：世界 → 逻辑

```lua
local cam = { x = 0, y = 0, zoom = 1 }

local function world_to_screen(wx, wy)
    return (wx - cam.x) * cam.zoom, (wy - cam.y) * cam.zoom
end

-- 画的时候
local sx, sy = world_to_screen(obj.x, obj.y)
wag.draw.draw_image(obj.img, 0, 0.0, sx - 4*scale, sy - 4*scale, 8*scale, 8*scale)
```

要点：

- **变换只在你这一侧**：引擎不提供摄像机 API（那是世界法则）；
- 你可以在不同的东西上用**不同的变换**（背景无缩放、角色有缩放）；
- 坐标算错的排查方法：先让摄像机静止、缩放 = 1，确认对象位置对，再逐层加变换。

## 三、几条经验

| 建议 | 理由 |
|---|---|
| 布局按 `render` 写，不按窗口写 | 窗口尺寸会变；`render` 是你定的设计空间 |
| 用一个函数做换算，别到处手算 | 手算的地方会各自漂移 |
| 逻辑坐标允许小数 | 不要因为"像素"就取整；引擎会按屏幕尺寸缩放 |
| y 向上为正 | 和数学习惯一致；屏幕坐标那一套（y 向下）只在帧缓冲内部用 |
| 不要自己乘 DPI | 引擎没有把 display_scale 用于几何；乘了会破坏窗口/视口 |

---

## 四、什么时候该建"第二套参考系"

你的游戏里若同时存在**两套坐标习惯**（例如"地图格坐标"和"UI 像素坐标"），
就显式建两个换算函数，**不要让它们混在同一个变量里**。

> 一个具体的坏味道：同一个 `x` 有时是格、有时是像素 ⇒ 总有一天会被混用一次，
> 而那一处的症状是"某个东西位置偏了 32 倍"，很难一眼看出。
