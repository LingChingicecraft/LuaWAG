# 平台给的参考系（只有一个）

> **引擎只认这一层坐标：逻辑坐标。**
> 世界怎么映射到它，是你的事（见同目录 `你自己的参考系.md`）。

---

## 一、逻辑坐标

| 项 | 值 |
|---|---|
| **原点** | **窗口中心** |
| x 轴 | 向右为正 |
| y 轴 | **向上为正** |
| 单位 | **项目逻辑单位**（不是窗口尺寸，也不是 DIP） |

⇒ 可见范围是 `render` 指定的矩形，**以原点为中心**：

```
左下角 = (−w/2, −h/2)
右上角 = (+w/2, +h/2)
```

所以 `(0, 0)` 永远在**屏幕中心**，与窗口多大无关。

---

## 二、可见范围（`render`）

世界的可见范围是**设计决定**，不是引擎猜的。启动时设定：

```lua
wag.space.set_viewport {
    render   = { w = 1920, h = 810 },   -- 可省略（= 保持不变）
    strategy = "letterbox",             -- **不可省略**
}
```

| 字段 | 规则 |
|---|---|
| `render` | 单位是项目逻辑单位；**可省略**（省略 = 不变） |
| `strategy` | `"letterbox"` 或 `"stretch"`；**不可省略**；**区分大小写**；未定义值直接报错（不回落） |

- `letterbox`：保持比例，多余处**留黑边**；
- `stretch`：拉满窗口，**会变形**。

### 什么时候生效

> **帧末生效**：本帧设的值，从**下一帧**起起作用。

所以第一帧用的是引擎默认值（1920×1080 信箱）—— 那是刻意的：保证第一帧永远合法（可能有黑边，但不变形）。

---

## 三、单位：窗口尺寸不是 DIP

当前平台的事实是：

```text
窗口尺寸 == 绘制表面像素
```

这是**因为当前没有启用高像素密度**，不是因为“DIP 等于像素”。

- 引擎**没有**实现 DPI-aware UI，也不会自动乘 1.5；
- 不要把窗口尺寸当 DIP；
- 不要用 `display_scale` 去乘窗口尺寸或除像素尺寸；
- 150% 缩放下，通常意义上的物理像素是窗口尺寸 × 1.5。

引擎内部的断言是：

```text
窗口尺寸 == 绘制表面像素（当前平台）
```

这是**输出窗口**的事实；0.2.0 的内部渲染目标尺寸是另一个量，
默认 1920×1080，由 `set_render_size()` 控制，用 `get_frame_size()` 查询。

它不是在说“DIP = 像素”，也不是在说“窗口尺寸 = 内部渲染目标”。

---

## 四、窗口尺寸变了会怎样

0.2.0 起，`render` 先映射到**内部渲染目标**；窗口尺寸/全屏只改变
“内部目标怎么呈现到输出”。

因此：

- `render` **不变**；
- 内部渲染目标**不自动跟随窗口**；
- 窗口变大/变小只影响 present 的缩放与黑边；
- 要改内部画布尺寸，显式调用 `set_render_size()`。

| 情况 | 变化 |
|---|---|
| 窗口变大 | 内部目标按 letterbox/stretch 放大到更大输出 |
| 窗口变窄 | 内部目标按策略缩小，可能黑边更多 |
| 全屏 | 只改输出；不自动改 `render` 或内部目标 |
| `set_render_size` | 改内部画布；窗口尺寸不变 |

⇒ **你的布局按 `render` 写**，不要按窗口写。按窗口写的布局，窗口一拖就散。

## 五、怎么读当前值

```lua
local vp = wag.space.get_viewport()     -- 当前生效的视口（内部目标坐标）
local w, h = wag.space.get_frame_size() -- 内部渲染目标像素
local ow, oh = wag.space.get_output_size() -- 输出 / 后缓冲像素
```

> 注意：`set_viewport` 帧末生效 ⇒ 本帧 `get_viewport()` 读到的可能还是**上一帧**的值。
> `get_viewport()` 的 viewport 矩形在内部目标坐标，不是输出窗口坐标。

## 六、整帧像素尺寸（**只给全屏效果用**）

0.2.0 起有两个不同的尺寸：

```lua
local iw, ih = wag.space.get_frame_size()    -- 内部渲染目标像素
local ow, oh = wag.space.get_output_size()   -- 输出 / 后缓冲像素
```

画全屏着色器四边形时，多数情况应使用**内部渲染目标**尺寸：

```lua
local w, h = wag.space.get_frame_size()
shader.draw_fullscreen(bg, w, h, nil, -10000, 0.0)
```

最终输出可能因为全屏、窗口尺寸或信箱策略而与内部尺寸不同；
真正的输出尺寸用 `get_output_size()` 查询。

| 项 | 说明 |
|---|---|
| 单位 | **物理像素**（不是 DIP，不要乘 DPI） |
| 时机 | **帧开始时定格**：一帧之内值不变 |
| 内部尺寸 | `get_frame_size()`，默认 1920×1080；由 `set_render_size` 控制 |
| 输出尺寸 | `get_output_size()`，窗口/全屏实际输出 |
| 它**不是** | 逻辑坐标范围 —— 那个是 `render`（默认 1920×1080） |

> ⚠️ **用途边界（纪律）**：像素尺寸只用于**整屏效果**（着色器全屏四边形、全屏遮罩、截图取景）。
> **不要**用它做游戏布局 —— 布局一律用逻辑坐标；用像素布局的代码一换窗口就整体崩。

**为什么不能拿它算缩放**：从 `render` 到内部目标、再从内部目标到输出的映射都是引擎的事
（信箱/拉伸策略），你自己再算一遍就是第二套真相。要“铺满可见区域”，让**着色器**用
`u_box`（见下）。

### 着色器侧：`u_box`

自定义片元着色器里可以拿到一个 uniform：

```glsl
uniform vec4 u_box;   // x, y, w, h —— 像素；y 以帧缓冲左下为原点
```

```glsl
vec2 uv = (gl_FragCoord.xy - u_box.xy) / u_box.zw;  // 0..1，y 向上
```

⇒ 这样无论窗口多大、是不是有黑边，背景都**正好铺满可见区域**，且不会变形。
