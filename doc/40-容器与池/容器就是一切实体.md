# 容器就是一切实体

## 一、只有一种东西

> **粒子、子弹、玩家、金币、地图单元、虚空判定、纯色矩形 —— 全都是同一个结构体的不同取值。**

引擎里**没有**"粒子系统""子弹类""玩家对象"这些不同的东西。只有一个结构体：**容器**。

| 你叫它什么 | 它的字段长什么样 |
|---|---|
| 粒子 | 有图、不参与碰撞、按速度移动 |
| 子弹 | 有图、参与碰撞、判定在脚本里 |
| 玩家 | 有图、参与碰撞、判定很小 |
| 纯色矩形 | 用内置 1×1 白图 + 尺寸 |
| 虚空判定（看不见） | 没有图、参与碰撞 |

⇒ **"是什么"由字段决定，不由类型决定。**

## 二、判据：能不能把它当成"一个东西"创建出来

```
能   ⇒ 它是**种类**（而种类只有"容器"）
不能 ⇒ 它是**围绕容器的结构**（池 / 索引 / 组）
```

这就是"通用"的意思：引擎不预设你有哪几种实体，只给你"实体"这一个概念。

---

## 三、术语：偏正结构，正词永远是实体

这条不是文风要求，是**设计纪律**：

| 写法 | 判定 | 为什么 |
|---|:--:|---|
| 粒子容器 / 子弹容器 | ❌ **禁止** | 正词是"容器" ⇒ 读起来像"装粒子的另一种东西" ⇒ 偷偷加回了"两类个体" |
| **容器粒子 / 容器子弹** | ✅ 允许 | 正词是实体，"容器"作修饰 ⇒ "一个粒子，而粒子的本质是容器" |
| "一个容器，它的字段是……" | ✅ 允许 | 描述具体取值时 |

> **一句话**：**"容器"只能当形容词，不能当名词中心。**
> 因为容器就是一切实体 —— 它不是一个"装东西的东西"。

---

## 四、你会遇到的三个"围容器"的东西

它们是**结构**，不是实体（不能 `new` 出来，也不该被当成个体）：

| 结构 | 是什么 |
|---|---|
| **池** | 容器的**存储**，每类一个，固定容量 |
| **索引** | `collides = true` 的容器在碰撞网格里的**投影** |
| **组** | 容器上的一个**标签**（`group`），用来决定"谁和谁查碰撞" |

> 常见误解：以为"碰撞对象住在索引里" ⇒ 听起来像第二种个体。
> 正确说法是：**索引替 `collides = true` 的容器建条目；条目只是它判定数据的投影。**

---

## 五、这对你写游戏意味着什么

| 你想 | 怎么做 |
|---|---|
| 加一种新东西 | 不用改引擎，**注册一个新的类**（用 `Lumi.Basic.object`），它还是容器 |
| 让两种东西长得一样但行为不同 | 用不同的字段组合，或两个类 |
| 让某东西"暂停时也动" | 放到 **Ext 帧线**（不是给容器加特权） |
| 让某东西不参与碰撞 | `collides = false`（出生时定，不能改） |
