# 池与句柄

## 一、池是什么

**池 = 容器的存储。** 每个类一个池，容量固定。

```
类 1 ──► 池 "class:1"   容量 32767
类 2 ──► 池 "class:2"   容量 32767
```

- 容量**固定**（不是按需增长）—— 引擎启动时一次性分配；
- 一个池装一个类的东西（`Lumi.Basic.object` 自动这样建）；
- 池有**名字**（诊断里能看到）。

## 二、⚠️ 池满 = 进程终止

> **一个类同时最多 32767 个。超过 ⇒ 进程直接终止**（引擎内部错误档，带弹窗）。

错误信息里会带**池名 / 容量 / 当前存活数**。

⇒ 这是"子弹一多就崩"的常见原因。对策：

| 对策 | 说明 |
|---|---|
| 及时 `kill` 不再需要的对象 | 回收后槽位立刻可复用 |
| 拆成两个类 | 两个池，各自 32767 |
| 做上限设计 | 玩家能造出来的东西必须有上限 |

## 三、句柄：不透明，只有三个用途

`b.handle` 是一个**不透明的数字**。它编码了"代号 + 池 + 下标"。

**可以做的三件事**：

```lua
object.kill(b.handle)          -- 交给引擎去杀
wag.container.alive(pool)      -- 统计（用池）
比较相等（==）                  -- 判断"是不是同一个"
```

**不能做的三件事**（做了不会立刻炸，但迟早炸）：

| 禁止 | 为什么 |
|---|---|
| **算术**（`h + 1`、`h > other`） | 它不是 ID，是打包值；顺序与"大小"毫无意义 |
| **序列化**（存盘、转字符串） | 下次启动后代号会变 ⇒ 旧句柄指向别的对象或直接失效 |
| **长期缓存**（存在别处跨帧用） | 对象回收后句柄**立即失效**；再用会让进程终止 |

> **要存盘就存你自己的逻辑标识**（比如"第 3 波第 5 颗"），不要存句柄。

## 四、句柄失效会怎样

**立即失效**，再用就会**让进程终止**（不是"返回 nil"，也不是"沉默"）。

容易踩的三个场景：

1. 对象 A 记着对象 B 的句柄，B 先死了 ⇒ A 下一帧用 B 的句柄 ⇒ 崩；
2. `replace` 换图后**旧句柄立刻失效** ⇒ 要换用新的；
3. 帧中途杀对象、同一帧稍后又用它 ⇒ 崩。

⇒ **建议**：需要"引用另一个对象"时，存**你自己的编号**并在用之前确认它还在。

## 五、查存活数

```lua
object.count()                 -- 全部类的总数（Lumi.Basic.object）
wag.container.alive(pool)      -- 单个池
```

> 池的存活数含"已标死但还没回收"的槽 —— 所以它可能略大于你的直觉。
> 水位达到 80% 时引擎会记一条 **L1**（预警），看到就该处理了。
