# 日志与诊断导出

## 一、日志

```lua
wag.log.info("标题", "细节")     -- 常规记录
wag.log.warn("标题", "细节")     -- 值得看一眼
wag.log.emit(wag.log.level.record, "标题", "细节")   -- 指定档
```

- 两段文字：**标题**（短、稳定，便于 grep）+ **细节**（可带数字）；
- 日志会打到控制台，也会进日志文件；
- `wag.log.level` 的键：`record` / `warn` / `terminate`（档名是**协议**，别自己编）。

> 建议：标题保持**稳定**（别把变量拼进标题），细节放变量 —— 否则没法按标题搜。

## 二、诊断导出（`--diagnostics`）

```bash
LuaWAG.exe --diagnostics
```

产物在 **exe 旁边**的 `debug/` 目录（不是当前工作目录）：

| 文件 | 内容 |
|---|---|
| `session.json` | 本次会话的元信息（进程 id、开始时间、工程名、引擎版本） |
| `perf_log.jsonl` | **每帧一行**：帧号、目标帧率、容器数、绘制调用数、本帧耗时 |
| `pool_log.jsonl` | 每秒一行：每个池的名字 / 容量 / 存活数 |
| `errors.jsonl` | 每条**未被捕获**的错误一行（含所在文件与行号） |

### 关键行为

- **惰性创建**：没有内容要写，就**不建目录、不建文件**；
- ⇒ **`errors.jsonl` 不存在是正常的**（说明没出错），不是故障；
- 不开 `--diagnostics` ⇒ **什么目录都不建**；
- 写文件与游戏行为**无关**：开不开诊断，行为逐字节相同。

## 三、拿这些文件干什么

| 想查 | 看哪个 |
|---|---|
| 卡顿 / 掉帧 | `perf_log.jsonl` 的 `frame_ms` 与相邻 `t` 的差 |
| 某个池快满了 | `pool_log.jsonl` 的存活 / 容量 |
| 出过错 | `errors.jsonl`（含 `file` 与 `line`） |
| 这次运行是不是我以为的那次 | `session.json` 的 `started_at` 与 `pid` |

> 这些是**机器可读**的（每行一个 JSON），可以直接喂给脚本或工具。

## 四、常见问题

| 现象 | 原因 |
|---|---|
| 找不到 `debug/` | 没开 `--diagnostics`，或找错了目录（在 **exe** 旁边） |
| `errors.jsonl` 不存在 | 正常：没有未捕获错误 |
| 有 `debug/` 但没有 `perf_log.jsonl` | 帧循环没跑起来（多半是没调 `wag.boot.run()`） |
