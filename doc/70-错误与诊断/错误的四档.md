# 错误的四档

> 引擎不按"严重程度数字"分类，按**行为**分类。你只需要知道**出了事会发生什么**。

---

## 一、四档行为

| 档 | 发生什么 | 典型来源 |
|---|---|---|
| **记录** | 只写日志，什么都不改变 | 池水位达 80%、拖拽开始/结束 |
| **脚本错误** | **报错 + 继续推进帧结构** | 钩子里的 Lua 错误、绘制越相位、同帧重复组对 |
| **内部错误** | **进程终止**（引擎自证不成立） | **池满**、**句柄失效**、贴图被卸载仍在用 |
| **致命** | **弹窗 + 进程终止** | 引擎必需件缺失、脚本显式声明"这是致命的" |

## 二、⚠️ "脚本错误"的"继续"是什么意思

> **继续的是帧结构，不是那次调用。**

```lua
-- 钩子里出了错
function MainFrameFunc(info)
    error("boom")            -- ← 这一帧的钩体余下部分不会执行
end                          -- ← 但后面的阶段照常走完、下一帧照常开始
```

⇒ 症状是"游戏还在跑，但某段逻辑没生效"，日志里有记录。

## 三、脚本能主动报错

```lua
wag.log.emit(wag.log.level.warn, "标题", "细节")   -- 只记日志
wag.log.info("标题", "细节")
wag.log.warn("标题", "细节")

-- ⚠️ wag.fail 收**表**，不是字符串；字段是 where / got / want / sentence
wag.fail {                                 -- 默认档 = warn（**只记录，不抛**）
    where = "我的参数检查",
    got   = tostring(x),
    want  = "一个 0..1 的数",
}

wag.fail {                                 -- 要"这次调用不生效" ⇒ 必须是 raise
    level = wag.log.level.raise,
    where = "我的参数检查",
    got   = "nil",
    want  = "一个表",
}

wag.fail { level = wag.log.level.terminate, -- 致命档：弹窗 + 终止
           sentence = "这局不能继续" }
```

**`wag.fail` 什么时候用**：参数不合法、状态不允许 —— 那种"这一步不该发生"的事。

## 四、你多半会碰到的三类

| 现象 | 属于 | 为什么会发生 |
|---|---|---|
| 游戏还在跑，但某段逻辑没执行 | 脚本错误 | 钩子里抛了错（最常见的是读写不存在的字段、调了不存在的函数） |
| **游戏直接没了** | 内部错误 | 池满（每类 32767）、用了已失效的句柄、贴图卸载后还在画 |
| **弹窗后退出** | 致命 | 引擎必需件缺失（引导脚本、Lua 状态）；或你显式 `wag.fail{level=terminate}` |

## 五、不要依赖的

- 不要依赖"报错之后那一帧还能正常跑完" —— 出错的那段逻辑**没有执行**；
- 不要用 `pcall` 把一切都包起来"反正引擎会继续" —— 你的状态可能停在半路。
