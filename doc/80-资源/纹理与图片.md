# 纹理与图片资源

> 这里讲“图片怎么进入引擎、怎么查、怎么卸”。
> 怎么画、层与混合见 `50-渲染/绘制与层.md`；帧序列的推进逻辑见本页末尾。

## 一、加载就是上传

```lua
local image = wag.image.load_from_file(
    "hero",
    resolve.luminosa_dir() .. "/Project/hero.png"
)
```

`load_from_file` 做三件事：

```text
读文件
解码成 RGBA
创建/上传 GPU 纹理
```

返回的是一个图片句柄，不是文件对象。

当前支持：

```text
.png
.bmp
```

不是“任意图片格式都行”。  
文件名不能以 `__` 开头，那是引擎保留名。

## 二、句柄不是文件名

```lua
local h = wag.image.lookup("hero")   -- 名字 → 句柄；不存在 nil
local w, h = wag.image.size(h)       -- 像素尺寸；失效 nil
```

句柄可以：

```text
传给 draw_image / draw_vertices / container.img
```

不要：

```text
对它做算术
存盘
跨脚本重载继续使用
```

## 三、卸载

```lua
wag.image.unload("hero")
```

幂等。  
但如果还有容器/绘制项引用这张图，卸载后再发射是错误，进程可能终止。  
卸载前先确认没人引用；或者干脆不卸载。

## 四、帧表

一张横排图可以切成多帧：

```lua
wag.image.define_frames(image, {
    { x = 0,   y = 0, w = 64, h = 64 },
    { x = 64,  y = 0, w = 64, h = 64 },
    { x = 128, y = 0, w = 64, h = 64 },
    { x = 192, y = 0, w = 64, h = 64 },
    { x = 256, y = 0, w = 64, h = 64 },
})

wag.image.frame_count(image)   -- 5；没有帧表时 nil
```

注意两件事：

- 帧矩形是**纹理像素**，不是 0..1。
- 帧表是**给容器发射用的**。`wag.draw.draw_image` 画的是整张图；要按帧画，用容器/`Lumi.Basic.object` 的 `frame` 字段。

## 五、锚点

```lua
wag.image.anchor(image, 0.5, 0.5)   -- 归一化锚点
local ax, ay = wag.image.anchor(image)
```

锚点只影响 `draw_image` 的位置解释；容器以中心为锚，不受这个影响。

## 六、帧序列怎么动

引擎只负责“按 `frame` 取哪一块图”。  
**不负责**“每几帧换一次”：

```text
frame 表：引擎提供
frame 推进：游戏 / 库负责
```

示例（启动画面测试用过）：

```lua
M.tick = M.tick + 1
if M.tick % 2 == 0 then
    M.frame_index = (M.frame_index + 1) % 5
    M.bullet.frame = M.frame_index
end
```

`Lumi.Basic.object` 的 `step` 会把 `frame` 写回容器。

## 七、失败等级

```text
文件不存在 / 解码失败 / 纹理槽满
→ L3，不是返回 nil 让你猜
```

`lookup` / `size` 这类查询才用 `nil` 表示“没有”。
